# Commands

All commands are run from within a git repository. Most require the repository to have at least one stack registered (via `sdf new` or `sdf fetch`).

## Stack management

<CommandRef command={cmd('branch')} />

<CommandRef command={cmd('sync')} />

Steps performed:

1. Fetch from origin and fast-forward the base branch
2. Query GitHub for the status of each PR in the stack
3. Reconcile PR states (mark merged nodes, fill in PR numbers)
4. For each downstream node that needs rebasing: rebase onto new parent, push
5. Update PR base branches on GitHub when a merged node is skipped
6. Optionally update PR titles and descriptions (with `--with-content` or if configured)
7. Update stack navigation links in all PR descriptions

Merged nodes remain in the stack JSON and are displayed as completed. They are not removed. The `ParentBranch()` function skips merged nodes to find the effective parent for rebasing.

**Conflict resolution:** When a rebase conflict occurs, an interactive menu is presented with these options:

- **Ask Claude to resolve** (if `claude` CLI is available)
- **I'll fix it myself** -- pauses sync; resume later with `sdf sync --continue`
- **Skip this branch** -- aborts the rebase for this branch, continues with the rest
- **Abort sync** -- stops the entire sync

After choosing "I'll fix it myself", resolve the conflicts manually, stage the files with `git add`, then run `sdf sync --continue`.

Fetches from origin and fast-forwards the base branch to ensure sync state is accurate. Shows each branch with its PR number, status (open/merged/closed), and whether it needs syncing. Also performs lightweight reconciliation against GitHub PR states and warns about structural drift.

<CommandRef command={cmd('split')} />

Uses Claude to analyze the source branch's commits and full diff, identify semantic themes, and propose a split plan. The plan groups changes into layers ordered by dependency (types/schema first, then APIs, then business logic, then UI). Each layer becomes a branch in the new stack.

**Pipeline:**

1. **Analysis** — Claude classifies each commit (clean, mixed, messy, dependent, scattered) and extracts themes that cut across commits
2. **Plan** — SDF generates a split plan showing layers, files, and estimated diffs. Saved as YAML for offline editing
3. **Review** — Interactive prompt to accept, refine (via Claude session), or abort
4. **Execute** — Creates branches using the appropriate strategy per layer: cherry-pick for clean commits, selective staging for mixed commits, hunk-level splitting for shared files
5. **Validate** — Verifies `git diff original-branch stack/last-branch` is empty (lossless split)
6. **Ship** — Pushes branches, creates PRs with stack navigation links

**Plan refinement:** Choosing "Refine plan" opens a Claude session where you can give natural language instructions to adjust the split (move files between layers, merge layers, rename layers). SDF re-extracts the updated plan automatically.

**Safety:** The original branch is never modified. If validation fails, the split is rolled back. Use `--dry-run` to preview the plan without executing.
